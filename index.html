Security by design 🔐

We're starting with a deliberately simple architecture.

Privacy-first prototype: this version does not collect accounts, passwords, payment details, or personal information. Calculator inputs are processed locally in the browser and are not sent to a server.

What we've done: strict content-security policy, no third-party JavaScript, safe DOM text updates instead of injecting HTML, input limits and numeric validation, no storage of sensitive data, and a design that can later be moved behind HTTPS.

Before payments or accounts: we'll add server-side validation, secure authentication, CSRF protection, rate limiting, secure cookies, database access controls, payment-provider checkout, audit logs, backups, and production security headers at the hosting layer.

Important: the security protections in this prototype are a starting point, not a guarantee that a future production system is secure. We should do a security review before accepting real money or sensitive user data.
